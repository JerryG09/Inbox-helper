## 1. Original discovery
R-REJ was found during the Day 3 AI-02 qualification (`47ca9c7`, `docs/evidence/day3-ai02/safety-findings.md`). Five plain rejection statements were not detected by the shared detector, so a model reply that falsely reported `unsupported_hiring_decision: false` would have been approvable. ## 2. Before-fix evidence
`before-fix-reproduction.txt` holds the verbatim run on the unchanged source: **5 expected-fail**. Each pin's assertion `containsHiringClaim(d) === true` failed, meaning the statement was undetected.

## 3. Correction and scope
Six affirmative-rejection patterns were added to the **one** shared detector `src/lib/safety/hiring-claims.ts`. It is consumed unchanged through `forbiddenDraft()` by:
- the server check in `provider.ts`
- `canApprove()` and `recheckDraft()` in `transitions.ts`

The six patterns:
1. "your application has been / was / is rejected, declined or unsuccessful"
2. "you (have / were / are) been rejected or declined"
3. "you (were / have / are) (been) not (been) selected, shortlisted, chosen, hired or successful"
4. "we will not / won't / are not / aren't / have decided not to … moving or proceeding or progressing forward"
5. "decided / chosen not to proceed, progress, move forward or continue with you or your …"
6. "you did not / didn't get the job, role, position or offer"

Existing clause logic is reused unchanged. A negation, uncertainty or conditional cue *before* the match, or a direct question, keeps the statement non-affirmative.

**Not changed:** provider prompt, model, parameters, schemas, concurrency, timeouts, retries, UI, CSS, CSV columns, frozen reference.

**Test-only change:** the fake upstream gained a `[[reject]]` marker.

## 4. Tests

## 8. Remaining limitations
- The detector remains a limited phrase-pattern safeguard. Other rejection phrasings can still pass, for example "Sadly, the position has gone to another candidate."
- Some unusual cautious sentences could now be blocked (a false positive). That is a safe failure, but it adds reviewer friction.
- A question-mark tag directly after a claim ("You were not selected?") is treated as a question (same behaviour as KL-2).
- Deferred and unchanged: F-HIST, KL-1..3, R-INJ, R-WD, R-PII, A11Y-01..03.
- Human review remains required. The detector is not comprehensive.
