# Day 3 unlearning observations — 29 October 2026

These are source notes for the final one-page note, drafted by Claude Code from this slice's actual test runs. Only lessons supported by today's evidence are listed.

| Previous working assumption | What today's evidence challenged | New practice | Evidence |
|---|---|---|---|
| A safety detector hardened through two P0 rounds (R1, R2) covers the obvious unsafe drafts | All existing hiring-claim tests passed, yet five plain **rejection** sentences were undetected, e.g. "Your application has been rejected." R1/R2 adversarial work had concentrated on positive claims (hire, offer, selection) | Build adversarial matrices by *category of harm* (positive claim, negative claim, completed action, third-party data), not by phrasing near the last bug. Pin each known gap with a test that flips when the gap closes | `test/live/adversarial-safety.test.ts` R-REJ; `docs/evidence/day3-ai02/safety-findings.md` |
| Unit fakes of SDK error objects prove the provider failure paths | Constructed `APIError` objects bypass the SDK's own retry layer, so the `maxRetries: 0` setting itself was never exercised. Pointing the real SDK client at a local HTTP fake made one-attempt behaviour observable. Mutation M4 (`maxRetries: 2`) then failed 4 tests | Test the boundary through the real client wherever it can run offline; mutation-check the configuration, not only the logic | `test/live/provider-http.test.ts`; M4 in `docs/evidence/day3-ai02/README.md` |
| "Max two concurrent calls" is a property of the server | The cap is per HTTP request. Two concurrent requests reached four in-flight provider calls | State the scope of every limit precisely; record it as a known limitation rather than imply a global cap | `provider-http.test.ts` "concurrency ceiling scope" |
| A strong test suite means every safeguard has a dedicated test | Mutation M1 (removing the operation-id equality check) was caught by **one** test only; the reset tests passed under it because reset already clears `activeOp` | Use mutations to find which single test guards each invariant, and treat single-point coverage as a review item | M1 in `docs/evidence/day3-ai02/README.md` |
