- No Anthropic or other model call was made by the app or by tests. All outcomes are simulated.

## Implementation
- `src/lib/processing/operation.ts` (new) — pure reconciliation:
  - Each operation has an immutable set of internal target keys.
  - Each active target settles exactly once.
  - A missing or duplicate outcome becomes an explicit failure.
  - A key outside the operation mutates nothing.
  - An adapter exception fails every target.
  - Diagnostics are content-free and capped at 20.
- `src/lib/import/state.ts`:
  - `startOperation`, `settleOperation`, `failOperation` and `resetState`.
  - The new fields `opSeq`/`activeOp` give one operation in flight with a monotonically increasing id. Results for a non-active id are recorded as `stale_result` and ignored.
  - Reset keeps `importSeq` and `opSeq`, so keys and operation ids are never reused.
  - `markProcessing`/`applyOutcomes` remain as wrappers over the strict path.
- `src/lib/processing/mock.ts`:
  - `simulateRetry` is the approved V1.1 recovery, bound to the exact M005 fixture.
  - `controlledAdapter` adds per-key fault injection: ok, fail, missing, duplicate, throw and delay.
  - `simulationAdapters()` is a client-only browser test hook.
- `src/app/page.tsx`:
  - Handlers and async settlement read refs holding the current state, not render closures.
  - `runOperation` serves both the reveal and retry paths.
  - Retry view and selection follow the prototype, then `normalizeView()` (UX-04-01).
  - Polite status announcements; focus moves to the nearest visible equivalent when the clicked control disappears.
- `InboxWorkspace` / `CandidateReview`: both retry controls are wired up. Their markup and classes are unchanged, except for an added `id="retryOne"`.

## Implementation

  - `anthropic` without a key is reported as *unavailable* and never falls back to simulation.

  - fixed request parameters: `max_tokens` 1600, thinking disabled, effort low, `output_config.format` JSON schema, no sampling parameters, `maxRetries` 0;
  - a 20 s timeout per attempt, also aborted if the browser disconnects, and at most 2 calls at once;

- `live-client.ts`: the browser adapter.
  - Only simulated mode reads `window.__MUST_SIM_PLAN__`.
  - The live response schema requires `source: "anthropic"`; anything else settles as failed.
- `operation.ts` / `state.ts`: a `live` flag on operations, so integrity failures in live mode are not worded as "Simulated".
- `forbiddenDraft` gained more hiring-outcome phrases; the same list now serves recheck, approval and the server check.
- Copy changes, UX-AI-01: see the evidence README table.
- Processing notice, UX-AI-02: `InboxWorkspace`.

## Problems and decisions
1. `JSON.stringify` does not escape `<`, so candidate text could close the untrusted-data delimiter. A unit test caught it; `<` is now escaped as `<`.
2. The browser timeout check used `instanceof DOMException`, which fails across realms (jsdom). It now matches on the error name.
3. SDK 1.x sends the API key as `Authorization: Bearer`. The fake upstream's key guard initially accepted only `x-api-key`, so it now accepts both. The guard stays in place: any key other than the fake one is refused with 401.
4. A live-mode browser test found the recheck button still reading "Run limited mock check". It is fixed, and the live end-to-end test now asserts there is no "mock"/"simulat" text in the Inbox and Results views.
5. `test/ui/app-shell.test.tsx` imported the client page directly. It now renders `InboxApp` in simulated mode; the assertions are unchanged.
6. Decision: no automatic chunking of large live batches. Imports over 10 show an explicit warning, and Start is disabled.
7. Decision: no provenance column in the CSV, to keep the 14-column contract. Provenance is shown in the UI.
8. Observation: genuine summaries for B and C used gendered pronouns inferred from names. The proposed prompt follow-up was not applied after acceptance.

## AI-01 R2 — Final P0 detector correction

This round closes three reproduced false negatives in the shared hiring-claim detector:
- **"Not only …"** was treated as a negation.
- **First occurrence only:** a later affirmative claim was missed.
- **Tag questions:** a claim followed by a tag question was skipped as a question.

**What changed.** The fix stays inside `hiring-claims.ts`:
- every occurrence of each pattern is evaluated;
- "not only" is stripped before the negation/conditional cue test;
- question suppression applies only to a claim in the final clause.

**Tests.**
- The tests failed before the fix: 6 failed, 60 passed.
- Each fix was then mutation-tested on its own, and every removal failed its own case.
- A fake-provider browser test covers "You have been selected, okay?".
