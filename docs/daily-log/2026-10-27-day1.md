The runner now opens new run files with `wx`, so it can never overwrite an existing run.

## Defects corrected
1. **Truncation was reported as `invalid_json`.** `stop_reason: max_tokens` is now a distinct `truncated` failure (`src/lib/eval/interpret.ts`). This holds even if the cut-off text happens to parse.
2. **Unavailable responses were scored as missed attention.** Scoring v2 (`src/lib/eval/score.ts`) changes this:
   - Each row has a status: `completed`, `truncated`, `processing_failure` or `missing`.
   - Attention metrics are computed over completed rows only, and unavailable rows are counted as `attentionUnassessable`.
   - Wrong attention flags are split into `missedAttention` and `falseAlarmAttention`.
   - Primary-intent accuracy is reported over all items and over completed items.
3. Original runs are re-scored into `eval/rescored/` by `eval/rescore.ts`, which never writes to the source file.

## Label adjudication
`docs/evaluation/label-adjudication-v0.2.md` covers E014, E016, E017, E019, E020 and E028. `eval/dataset/v0.2.json` is **proposed only** (`proposed_v0.2_pending_owner_review`). It differs from v0.1 in exactly those six items, which a test enforces.

## Truncation-recovery experiment (authorized: E017 and E028 only)
- **Run:** `eval/runs/2026-10-27T09-59-39-835Z-llm-recovery.json` at 2026-10-27T09:59:39Z.
- **Settings:** same model (`claude-haiku-5-5`, confirmed in the response) and same prompt (`classify-v1`, system prompt byte-identical). Dataset v0.1. The only change was `max_tokens` 800.

| ID | Original (max 400) | Recovery (max 800) | Output tokens (of which thinking) | Input tokens | Latency |
|---|---|---|---|---|---|
| E017 | truncated; partial primary `withdrawal` | `end_turn`; `other_unclear`, no secondary, attention ✓ | 512 (389) | 615 | 3,714 ms |
| E028 | truncated; partial `other_unclear` + `application_status` | `end_turn`; `other_unclear`, no secondary, attention ✓ | 211 (54) | 631 | 1,588 ms |

- Both outputs passed the schema, with no errors. Total: 1,246 input tokens and 723 output tokens.
- Scored against v0.1: primary 1 of 2, recall 0.25, attention 2 of 2. Scored against proposed v0.2: primary 2 of 2, recall 0.5, attention 2 of 2.

### Interpretation
- **Root cause of the truncation:** the API reports `output_tokens_details.thinking_tokens`, and those count against `max_tokens`. E017 spent 389 tokens on internal reasoning before writing the answer. That is why a roughly 100-token JSON answer could run out at 400.
- **Not a full-batch measurement.** This is a 2-item recovery check, and its numbers must not be merged into run 2's 30-item accuracy.
- **Not deterministic.** E017's primary changed between calls (`withdrawal` in the partial output, `other_unclear` now), and temperature can no longer be controlled. So this run shows the truncation can be avoided; it does not show that the classification is stable.
